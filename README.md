# 패밀리오피스 상담 예약 시스템

모바일 우선으로 만든 상담 예약 사이트입니다. 파일 하나(`index.html`)로 동작하며 GitHub Pages에 그대로 올릴 수 있습니다.

## 화면 구성

| 주소 | 대상 | 내용 |
|---|---|---|
| `/#book` | 손님(PB) | 분야 선택 → 날짜 → 08~18시 시간 바에서 시작 시간 선택(상담 시간만큼 자동 선택) → 이름·비밀번호 입력 |
| `/#mine` | 손님(PB) | 이름 + 비밀번호(숫자 4자리)로 내 예약 조회, 변경, 취소 |
| `/#admin` | 관리자 | 예약 관리, 분야별 일정 열기, 분야 관리, 기본 설정 |

관리자 로그인: 아이디 `hanafo` / 비밀번호 `3771`. 이 값은 `index.html` 상단의 `ADMIN_ID`, `ADMIN_PW`에 있습니다.

## 주요 규칙

- **상담 가능 시간**: 08:00~18:00, 30분 단위입니다. 관리자가 분야별로 날짜를 여러 개 고른 뒤 시간대(예: 종일, 오전, 오후, 직접 지정)를 한 번에 저장합니다.
- **이동시간(버퍼)**: 상담 장소가 매번 다를 수 있으므로, 상담이 끝난 뒤 기본 60분 동안은 손님이 예약할 수 없습니다.
  - 기본값은 관리자 › 설정에서 0, 30, 60, 90, 120분 중에서 바꿉니다.
  - 예약마다 따로 바꾸려면 관리자 › 예약 카드에서 고칩니다.
  - 관리자가 직접 예약을 등록하거나 수정할 때는 이동시간을 무시하고 넣을 수 있습니다. 상담 시간 자체가 겹치면 등록되지 않습니다.
- **담당 전문가 공유**: 분야가 달라도 담당 전문가 이름이 같으면 한 사람의 일정으로 보고 겹침을 함께 계산합니다.
- **동시 예약 방지**: 저장 직전에 해당 일자를 잠그고 다시 확인합니다. Firestore에서는 트랜잭션을 씁니다.

## Firebase 연결 (실제 운영용, 약 5분)

`config.js`를 비워 두면 **체험 모드**로 동작합니다. 체험 모드에서는 예약이 접속한 브라우저에만 저장됩니다. 여러 사람이 같이 쓰려면 아래 순서로 무료 Firebase 저장소를 연결해야 합니다.

1. <https://console.firebase.google.com>에서 **프로젝트 추가**를 누릅니다. 애널리틱스는 꺼도 됩니다.
2. 왼쪽 메뉴 **Databases & Storage › Firestore**에서 **데이터베이스 만들기**를 누릅니다. 화면에 따라 메뉴 이름이 **빌드 › Firestore Database**로 나올 수도 있습니다. 에디션은 **Standard**, 위치는 `asia-northeast3 (서울)`, 보안 규칙은 **프로덕션 모드**를 고릅니다.
3. Firestore의 **규칙** 탭에 이 저장소의 `firestore.rules` 내용을 붙여 넣고 **게시**합니다.
4. **프로젝트 설정(톱니바퀴) › 내 앱 › 웹 앱 추가(</>)**에서 앱을 등록한 뒤, 화면에 나오는 `firebaseConfig = { ... }` 객체를 복사합니다.
5. 이 저장소의 `config.js`를 GitHub에서 열고 연필 아이콘(편집)을 누릅니다. `window.FIREBASE_CONFIG = null;`을 `window.FIREBASE_CONFIG = { ...복사한 내용... };`으로 바꾸고 **Commit changes**를 누릅니다.
6. 1~2분 뒤 사이트를 새로고침합니다. 상단의 "체험 모드" 띠가 사라지면 연결된 것입니다.
7. `/#admin`에 로그인한 뒤 **분야 › 샘플 분야 6개로 시작하기**를 누르거나 분야를 직접 추가합니다.

## 보안 관련 안내

이 사이트는 서버 없이 동작하는 정적 사이트라서 다음과 같은 한계가 있습니다.

- 관리자 아이디와 비밀번호가 페이지 소스에 들어 있어, 소스를 열어 보면 누구나 확인할 수 있습니다.
- Firestore 규칙이 열려 있어 사이트 주소를 아는 사람은 예약 데이터(이름, 지점, 요청사항)를 읽고 쓸 수 있습니다.
- 손님 비밀번호는 원문 대신 해시로 저장하지만, 숫자 4자리라 강한 보호는 아닙니다.

사내 테스트나 내부용으로는 쓸 수 있습니다. 외부 고객에게 공개하기 전에는 Firebase Authentication으로 관리자 계정을 분리하고, 규칙을 "관리자만 쓰기 가능"으로 좁혀야 합니다.

## 파일

- `index.html`: 화면과 동작 전체
- `config.js`: Firebase 설정 (비우면 체험 모드)
- `firestore.rules`: Firestore 보안 규칙
